# lib389 Object API

lib389 (`src/lib389/lib389/`) is the Python management library used by the test suites and the CLI tools. Nearly every LDAP entry is managed through a subclass of `DSLdapObject` (one entry) or `DSLdapObjects` (a container), both defined in `src/lib389/lib389/_mapped_object.py`. CLI wiring on top of this API: [cli.md](cli.md). How tests obtain server instances: [testing.md](testing.md).

## Object model

Before writing raw LDAP calls or a new class, look for an existing wrapper: subclasses of both base classes fill `src/lib389/lib389/` (`backend.py`, `plugins.py`, `replica.py`, `config.py`, `idm/`, ...). A wrapper is a pair of classes whose behavior is driven entirely by class attributes assigned in `__init__` **after** the `super().__init__(...)` call:

| Attribute | Side | Purpose |
|---|---|---|
| `_rdn_attribute` | singular | naming attribute used to derive the DN |
| `_must_attributes` | singular | keys required in `properties` on create |
| `_create_objectclasses` | singular | objectClass values written on create |
| `_protected` | singular | must be set `False` to allow `delete()`/`rename()` |
| `_compare_exclude` | singular | attributes ignored by strict `ensure_state` comparison |
| `_objectclasses` | plural | objectclass terms of the container search filter |
| `_filterattrs` | plural | attributes matched by `get(selector)` |
| `_childobject` | plural | singular class returned by `get()`/`list()` |
| `_basedn` | plural | container search base |

The singular side uses `_create_objectclasses`, the plural side uses `_objectclasses` — different names for different jobs; do not swap them. Reference implementations: `src/lib389/lib389/idm/group.py` (`Group`/`Groups`) and `src/lib389/lib389/idm/user.py` (`UserAccount`/`UserAccounts`).

```python
# Singular side: Group.__init__ (idm/group.py)
self._rdn_attribute = 'cn'
self._must_attributes = ['cn']
self._create_objectclasses = ['top', 'groupOfNames']
self._protected = False        # else delete()/rename() silently no-op
```

```python
# Plural side: Groups.__init__ (idm/group.py)
self._objectclasses = ['groupOfNames']   # search filter, NOT _create_objectclasses
self._filterattrs = ['cn']               # what get(selector) matches
self._childobject = Group
self._basedn = f'{rdn},{basedn}'
```

## Silent failures

These fail without an exception or a log line. Check this list first when a lib389 call "does nothing".

- **`delete()` and `rename()` silently return when `_protected` is True.** `DSLdapObject.__init__` defaults `_protected = True`, so every subclass inherits protection unless it sets `_protected = False` — a new wrapper that forgets it cannot be deleted and gives no clue why. See `_mapped_object.py` (`DSLdapObject.delete`, `DSLdapObject.rename`). `Account` sets it False (users are deletable); `Plugin` and `Config` stay protected on purpose.
- **`ensure_state(strict=False)` (the default) reports "updated" even when nothing changed.** On an existing entry it issues a `MOD_REPLACE` for every supplied attribute with no comparison. Only `strict=True` compares values and can leave `ensure_status` at `"unchanged"`. See `_mapped_object.py` (`DSLdapObject._create`). Do not confuse it with `ensure_attr_state(state)` — a different method that diffs per value and where an empty list deletes the whole attribute.
- **`DSLdapObjects.exists()` swallows every exception.** Its search is wrapped in a bare `except:` returning False, so False can mean "connection error", not "entry absent". See `_mapped_object.py` (`DSLdapObjects.exists`).
- **`DSLdapObjects.filter(attrlist=...)` permanently mutates the container.** Passing `attrlist` assigns `self._list_attrlist`, so later `list()` calls on the same container return the narrowed attribute set. See `_mapped_object.py` (`DSLdapObjects.filter`).
- **`remove_all(key)` is a silent no-op when the attribute is absent** — it swallows `ldap.NO_SUCH_ATTRIBUTE`. See `_mapped_object.py` (`DSLdapObject.remove_all`).

## Creating entries

Singular and plural `create` differ in arity: singular is `create(rdn=None, properties=None, basedn=None)`; plural is `create(rdn=None, properties=None)` and passes its own `_basedn` down. Test and CLI code normally uses the plural form:

```python
users = UserAccounts(inst, DEFAULT_SUFFIX)
user = users.create(properties={
    'uid': 'jdoe', 'cn': 'jdoe', 'sn': 'doe',
    'uidNumber': '1000', 'gidNumber': '2000',
    'homeDirectory': '/home/jdoe',
})
```

`DSLdapObject._validate` rules (see `_mapped_object.py`):

- **Int values raise `AttributeError`** — `ensure_bytes` calls `val.encode()`. Stringify numerics: `'uidNumber': str(uid)`.
- **The properties dict is mutated in place** (scalars are wrapped into lists), so a shared module-level dict such as `TEST_USER_PROPERTIES` is modified by a create call. Pass a copy.
- A missing `_must_attributes` key raises `ldap.UNWILLING_TO_PERFORM`. One exception: when the missing must-attr is the `_rdn_attribute` and `rdn` was given, the value parsed from the rdn is back-filled.
- A subclass that forgets `_create_objectclasses` fails with a bare `AssertionError` from `DSLdapObject._create`, not an LDAP error.

`ensure_state` outcomes are read from the `ensure_status` property: `"added"`, `"updated"`, or `"unchanged"`.

## Reading and writing

Getter matrix on `DSLdapObject` (`get_attrs_vals*` take a list of names and return a dict; `get_attr_vals*` take one name and return a list):

| Wanted | one attr, one value | one attr, all values | several attrs | whole entry |
|---|---|---|---|---|
| bytes | `get_attr_val` | `get_attr_vals` | `get_attrs_vals(keys)` | `get_all_attrs()` |
| str | `get_attr_val_utf8` | `get_attr_vals_utf8` | `get_attrs_vals_utf8(keys)` | `get_all_attrs_utf8()` |
| lowercased str | `get_attr_val_utf8_l` | `get_attr_vals_utf8_l` | — | — |
| explicit bytes | `get_attr_val_bytes` | `get_attr_vals_bytes` | — | — |
| int | `get_attr_val_int` | `get_attr_vals_int` | — | — |

- `get_attr_val` returns **bytes**, not str, and has two distinct empty results: attribute absent on an existing entry returns `None`, while a base search matching zero entries returns `''` (a missing DN raises `ldap.NO_SUCH_OBJECT` instead). `get_attr_val_utf8` inherits both, so calling `.lower()` on its result crashes on an absent attribute — **prefer `get_attr_val_utf8_l` for comparisons**; it None-guards. The plural `get_attr_vals*` forms return `[]`.
- Writes: `add(key, value)`, `replace(key, value)`, `remove(key, value)` are wrappers over `set(key, value, action=...)`, one modify each. Batch atomically with `add_many((k, v), (k2, v2))` / `replace_many(...)` (bare tuples, no wrapping list) or `apply_mods([(action, key, value), ...])` — the 2-tuple form `(ldap.MOD_DELETE, key)` is allowed only for deletes; any other 2-tuple or unknown action raises `ValueError`. Values are byte-encoded for you.
- **ONLINE guard**: the getters above plus `set()` and `present()` raise `ValueError("Invalid state. Cannot ... not ONLINE")` unless `instance.state` is online. Offline work goes through `DSEldif`, not DSLdapObject.
- `DSLdapObjects.get(selector)` raises `ldap.NO_SUCH_OBJECT` on zero matches and `ldap.UNWILLING_TO_PERFORM` on more than one. The selector is escaped with `escape_filter_chars`, so `*` is useless as a selector — use `list()` to enumerate.

## DirSrv lifecycle

- State machine: `DirSrv()` → `allocate()`/`local_simple_allocate()` → `create()` → `open()`; state moves INIT → ALLOCATED → OFFLINE → ONLINE. `DirSrv.create` raises `ValueError` unless the state is ALLOCATED; `close()` returns to OFFLINE.
- **Broker attributes attach only in `open()`.** `inst.config`, `inst.backends`, `inst.plugins`, `inst.replicas`, `inst.tasks`, `inst.schema`, `inst.monitor`, `inst.aci`, `inst.encryption`, and the rest are created by `DirSrv.__add_brookers__` — the final statement of `DirSrv.open` (`src/lib389/lib389/__init__.py`). Touching them before `open()` raises `AttributeError`. After open, use `inst.config.set(...)` rather than constructing `Config(inst)` yourself.
- **`Account.bind(password)` returns a NEW bound connection** (it clones the instance); it does not rebind the current one, so keep the return value. `Account.rebind(password)` rebinds the same connection. See `src/lib389/lib389/idm/account.py`.
- **`DirSrv.exists()` is a filesystem check** — "is this instance installed here" — not an LDAP entry check; that is `DSLdapObject.exists()`.
- Tests never build `DirSrv` objects by hand; instances come from the topology fixtures described in [testing.md](testing.md).

## Deprecated vs modern

`DirSrv` wraps the raw python-ldap methods inherited from `SimpleLDAPObject` (`wrapper` in `src/lib389/lib389/__init__.py`) and emits a `DeprecationWarning` naming the caller unless the call passes `escapehatch='i am sure'`. Raw calls remaining in old tests are **not** precedent for new code — always use the objects API:

| Legacy call | Modern replacement |
|---|---|
| `inst.add_s(entry)` | `<Objects>(inst, basedn).create(rdn, props)` |
| `inst.modify_s(dn, mods)` | `obj.replace()` / `add()` / `remove()` / `set()` / `apply_mods()` |
| `inst.delete_s(dn)` | `obj.delete()` |
| `inst.search_s(...)` / `inst.search_ext_s(...)` | `<Objects>.list()` / `get()` / `filter()` |
| `inst.simple_bind_s(dn, pw)` / `inst.bind_s(...)` | `account.bind(pw)` / `account.rebind(pw)` |
| `inst.modrdn_s(...)` / `inst.rename_s(...)` | `obj.rename(new_rdn, newsuperior=...)` |
| `inst.unbind_s()` | `inst.close()` |
| `inst.getEntry(dn, ...)` | `obj.get_attr_val_utf8()` / `<Objects>.get(dn=...)` |

## idm specifics

- **`UserAccounts(inst, DEFAULT_SUFFIX)` operates under `ou=People,<suffix>`, not the suffix** — the constructor prepends its `rdn` argument (default `ou=People`) to `basedn`. Pass `rdn=None` to make the container the suffix itself. `Groups` does the same with `ou=Groups`; `nsUserAccounts` defaults to lowercase `ou=people`. The default can also be moved by `people_rdn`/`groups_rdn` keys in `~/.dsrc`.
- Must-attribute sets differ per class: `UserAccount` (classic) requires `uid`, `cn`, `sn`, `uidNumber`, `gidNumber`, `homeDirectory`; `nsUserAccount` (modern, DS >= 1.4.0) replaces `sn` with `displayName`. Using the wrong set is the most common create failure. See `src/lib389/lib389/idm/user.py`.
- `UserAccounts.create_test_user(uid=1000, gid=2000)` is the test one-liner: rdn `uid=test_user_<uid>` with all must-attributes filled in.

## Constants and paths

- `src/lib389/lib389/_constants.py`: `DEFAULT_SUFFIX = 'dc=example,dc=com'` (and its duplicate `SUFFIX`), `DN_DM = 'cn=Directory Manager'`, `PW_DM = 'password'`, `PASSWORD = 'password'`, `DEFAULT_BENAME = 'userRoot'` (case sensitive), `ReplicaRole` enum (`CONSUMER`/`HUB`/`SUPPLIER`/`STANDALONE`), `DSRC_HOME = '~/.dsrc'`.
- Topology constants (`PORT_STANDALONE1`, `SERVERID_SUPPLIER_1`, `PORT_CONSUMER_1`, ...) are generated at import time by `setattr` loops in the same file — **they exist at runtime but are invisible to grep and IDEs**. The port scheme is deterministic: standalone1 = 38901, supplier1 = 39001, hub1 = 39101, consumer1 = 39201; secure port = port + 24700.
- `src/lib389/lib389/paths.py` (`Paths._get_defaults_loc`) resolves `defaults.inf`: when the `PREFIX` env var is set and non-empty, **only** `$PREFIX/share/dirsrv/inf/defaults.inf` is tried (`IOError` on a miss); otherwise the first existing entry of `/usr/share`, `/usr/local/share`, `/opt/dirsrv/share`, `/opt/local/share`, `/opt/share` (each + `dirsrv/inf/defaults.inf`).
- `ds_is_older(...)` / `ds_is_newer(...)` in `src/lib389/lib389/utils.py` read the server version from `defaults.inf`, so they need an installed server; `get_default_db_lib()` reads the `NSSLAPD_DB_LIB` env var (default `mdb`).

## Lint framework

`DSLint`/`DSLints` in `src/lib389/lib389/_mapped_object_lint.py` power `dsctl healthcheck`: a class gains checks by defining a `lint_uid()` classmethod and generator methods named `_lint_<name>` that yield report dicts. A check only runs from the CLI if its class is registered in `CHECK_OBJECTS` in `src/lib389/lib389/cli_ctl/health.py`.
